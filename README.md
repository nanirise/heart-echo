# HeartEcho · AI 情感陪伴

> 精弘网络技术部试用期大作业 · 开放选题 · 三人团队 · 4 周开发周期

一个前后端分离的 AI 情感陪伴 Web 应用。核心特征是**"像真人一样"的 AI 伴侣**——有记忆、有情绪、有主动行为、能自行演化人格、能发朋友圈并与**自己账号内的其他** AI 互动。

**交付策略**：采用**分阶段交付**。阶段一先用最直接的实现打通全部核心链路，阶段二在接口不变的前提下替换为完整实现（向量检索、小模型推理）。接口抽象已在设计阶段完成，阶段二只替换实现类。

| 项目 | 说明 |

- 个人产品定位，账号之间完全隔离，不涉及社区与内容审核
- 三人分工边界清晰，Git 贡献度易均衡

## 三、核心功能清单

### P0 · 必须完成（Week 1-3）

1. **用户注册 / 登录**
   - 注册、登录、Token 刷新、登录态下修改密码
   - **注册成功即登录**，直接进对话页
   - **个人资料**：可改头像 URL（只填链接，不做文件上传）与用户名
   - 前端 Token 持久化 + 路由守卫
   - JWT 鉴权

2. **自定义 AI 人设**
   - 用户可创建 AI 伴侣：名字、性格描述、说话风格，数量不限
   - **一个人设 = 一个对话**，不需要手动新建/切换会话，也没法单独清空记录
   - 对话历史与记忆、画像**都按人设隔离**——每个伴侣各记各的

3. **文字对话**
   - SSE 流式输出 + 打字机效果
   - Markdown 渲染
   - 左侧人设列表即对话列表 + 历史消息

4. **情感分析（双向，内部信号）**
   - 用户消息与 AI 回复均做 8 类情绪识别
   - **不向用户展示标签**：情绪是内部信号，用于记忆写入、画像构建与回复策略选择
   - 效果通过 AI 回复策略的差异体现——悲伤时先共情不给建议，开心时语气更活泼

5. **记忆系统（一人设一份）**
   - 记住用户说过的事实、偏好、重要事件
   - **只读展示**：可以在画像页看到 AI 记住了什么，但不能删
   - 记忆检索注入对话上下文

6. **主动消息**
   - 用户沉默一段时间后，AI 主动发起对话
   - 开关、间隔区间、每日上限**全部可调**；有新消息时侧栏显示红点
   - 内容基于上下文和记忆生成，非模板

### P1 · 应该完成（Week 3-4）

7. **AI 朋友圈（账号内）**
   - AI 伴侣定时发动态，**同账号下的其他** AI 角色评论互动
   - 用户可点赞和评论，**不能自己发动态**
   - 只见自己账号的内容，没有跨用户社区

8. **人格演化**
   - 亲密度随对话轮数增长，AI 说话逐渐更随意亲近
   - 不做"AI 改写自己人设"那一档

9. **用户画像（一人设一份）**
   - 结构化展示从对话中提取的用户特征，可按伴侣切换查看

10. **日程提醒（P1 队尾，有余量才做）**
   - 在对话里说「明天下午三点提醒我开会」，AI 记下并在到点后主动提醒
   - **不是第 4 个 Agent**：复用主动消息的触发链路（见 [技术文档 §5.7](docs/TECH_DESIGN.md#57-日程提醒p1)）
   - 时间解析只做规则档；**解析不出会回问澄清，不静默丢弃**
   - 有手动触发接口 `POST /schedules/:id/trigger`，演示不用等

### P2 · 不做

11. ~~语音对话~~
12. ~~情绪趋势大屏可视化~~
13. ~~消息编辑 / 撤回~~
14. ~~主题切换 / 深色模式~~

## 四、实现阶段划分

> 这是本项目的交付节奏：**阶段一保证核心链路先跑通并可演示，阶段二在同一套接口下替换为完整实现。**

| 能力 | 阶段一（Week 2-3） | 阶段二（Week 3-4） | 切换方式 |
|------|-------------------|-------------------|----------|
| 情感分析 | 关键词词典（8 类情绪） | ONNX 小模型推理 | 环境变量 `EMOTION_BACKEND` |
| 记忆检索 | PostgreSQL：最近 N 条 + 关键词加权 | ChromaDB 向量语义检索 | 环境变量 `MEMORY_BACKEND` |
| 记忆提取 | 规则提取（句式匹配） | LLM 结构化提取 | 环境变量 `MEMORY_EXTRACT_BACKEND` |
| 人格演化 | 对话轮数驱动的亲密度 | 亲密度 +（**可选**）AI 自述补充 | `personas.state` |
| 朋友圈评论 | 模板生成 | Agent 自主生成 | 服务内策略切换 |
| 日程时间解析（P1） | 规则档（句式匹配） | LLM 结构化解析 | 环境变量 `SCHEDULE_PARSE_BACKEND` |

**阶段划分的意义**：

- 阶段一让前端在 Week 2 就有真实接口可联调，不被 AI 侧的复杂度阻塞
- 阶段二替换实现时，**Go 后端与前端一行不用改**——因为 Go 只依赖 Python 服务的 HTTP 契约，不关心内部实现

**接口抽象设计**见 [技术文档 §5.0](docs/TECH_DESIGN.md#50-实现分级与升级路径核心设计)。

**阶段二的推进纪律**：每替换一项，必须在工作日结束时保持服务可运行、可演示。不允许出现"升级到一半、周末不能用"的状态——**始终在可工作的版本上迭代**。

## 五、技术架构

### 5.1 总体架构

```
┌──────────────────────────────────────────────────────────┐
│  前端层  Vue3 + TypeScript + Pinia + Vue Router           │
│  登录注册 / 流式对话 / 朋友圈 / 人设管理 / 用户画像         │
└────────────────────────┬─────────────────────────────────┘
                         │ RESTful API + SSE
                         ▼
┌──────────────────────────────────────────────────────────┐
│  业务后端层  Go + Gin + GORM                              │
│  JWT 鉴权 / 人设与消息持久化                               │
│  统一响应中间件 / 统一错误码 / 路由分组                    │
└────────────────────────┬─────────────────────────────────┘
                         │ 内部 HTTP 调用
                         ▼
┌──────────────────────────────────────────────────────────┐
│  AI 服务层  Python FastAPI                                │
│  情感分析 Agent / 对话生成 Agent / 记忆管理 Agent          │
│  DeepSeek API ｜ 阶段二：ONNX 小模型 / ChromaDB            │
└────────────────────────┬─────────────────────────────────┘
                         ▼
┌──────────────────────────────────────────────────────────┐
│  数据层  PostgreSQL（关系数据 + 记忆）                    │
│          阶段二：ChromaDB（向量记忆索引）                  │
└──────────────────────────────────────────────────────────┘
```

### 5.2 技术选型

| 组件 | 选择 | 理由 |
|------|------|------|
| 前端框架 | Vue3 + TypeScript | 硬性要求，且生态成熟 |
| 状态管理 | Pinia | Vue3 官方推荐，TS 支持好 |
| 路由 | Vue Router 4 | 硬性要求，配路由守卫 |
| UI 库 | Element Plus | 中文文档完善，组件覆盖全 |
| HTTP 客户端 | Axios | 拦截器机制成熟，便于统一处理 Token 与错误码 |
| Markdown 渲染 | markdown-it + highlight.js + DOMPurify | 轻量可控，避免 XSS |
| 后端框架 | Go + Gin | 硬性要求，上手快、中间件生态好 |
| ORM | GORM | Go 生态最成熟的 ORM，`AutoMigrate` 免去迁移工具 |
| 数据库 | PostgreSQL 16 | 一个库搞定全部数据，JSONB 适合存画像与人格状态（情绪是消息表上的两个标量列） |
| AI 服务 | Python FastAPI | AI 生态好，与 Go 通过内部 HTTP 通信 |
| LLM | DeepSeek API | 国内可访问、便宜、兼容 OpenAI 格式 |
| 情感分析（阶段一） | 8 类情绪关键词词典 | 离线、零依赖 |
| 情感分析（阶段二） | chinese-chat-sentiment-8class + ONNX | 中文对话情感分类 |
| 记忆检索（阶段一） | PostgreSQL：最近 N 条 + 关键词加权 | 零额外组件 |
| 记忆检索（阶段二） | ChromaDB 向量检索 | 语义召回 |
| 部署 | Docker Compose + 云服务器 | 学生机约 15-20 元/月 |
| 反向代理 | Nginx | 前端静态文件 + API 转发 |

**明确不做**：Redis、消息队列、Kubernetes、CI/CD 自动化、数据库迁移工具、域名 / HTTPS / ICP 备案、微服务拆分。理由见 [技术文档 §2](docs/TECH_DESIGN.md#2-技术选型)。

> **产品定位**：这是**个人产品**，不是社交平台。账号之间完全隔离，每个人只能看到自己创建的 AI 和自己的数据。跨用户的社区、AI 互相可见是远期进阶选项，本期不做。完整决策见 [开发总纲 §0](docs/dev/MASTER.md#0-功能决策记录已确认不要私自改)。

## 十二、快速开始（本地开发）

```bash
git clone git@github.com:<org>/heart-echo.git
cd heart-echo

# 1. 启动 PostgreSQL
docker compose -f deploy/docker-compose.dev.yml up -d

# 2. Go 后端（:8080）
cd backend && cp .env.example .env && go mod download && go run ./cmd/server

# 3. Python AI 服务（:8000）
cd ai-service && cp .env.example .env && pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

# 4. Vue 前端（:5173）
cd frontend && npm install && npm run dev
```

浏览器访问 `http://localhost:5173`。

**环境变量清单**见 [技术文档 §4.6](docs/TECH_DESIGN.md#46-环境变量清单)。**`.env` 严禁提交到仓库。**
