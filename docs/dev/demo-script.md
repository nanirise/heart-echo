## 1. 演示步骤

> 每步格式：**在哪 → 做什么 → 看到什么**。
> ✅ = 预期正常；⚠️ = 已知风险点。

### 第 1 步：登录

| 项 | 内容 |
|---|---|
| **在哪** | 浏览器打开演示地址 → `/login` |
| **做什么** | 输入 `demo` + 密码 → 点「登录」 |
| **看到什么** | ✅ 跳转到 `/chat`，侧栏显示用户名 `demo` |
| **原理一句话** | 登录拿到 accessToken，存进 Pinia 并持久化（`heart-echo-auth`），刷新不掉登录 |

⚠️ **风险**：生产环境的 `VITE_API_BASE_URL` 若仍指向 `localhost:8080`，线上会登录失败。见第 4 步。

---

### 第 2 步：看人设（已有 2 个）

| 项 | 内容 |
|---|---|
| **在哪** | 点侧栏「人设」→ `/personas` |
| **做什么** | 不用操作，看网格 |
| **看到什么** | ✅ 2 张人设卡片（小满 / 阿哲），各显示亲密度、最近对话时间 |

> 若现场演示「创建人设」：点「新建人设」→ 填 3 个字段 → 保存 → 列表刷新出现。
> ⚠️ 保存后是**重新拉列表**（不是本地插排），所以会有一次短暂加载。

---

### 第 3 步：对话（**核心环节**）

| 项 | 内容 |
|---|---|
| **在哪** | 点侧栏「对话」→ `/chat` |
| **做什么** | 左侧选中「小满」→ 输入框打字 → 发送 |
| **看到什么** | ✅ 先出现**打字指示器** → 随后回复**逐字出现**（流式） |
| **原理一句话** | 前端用 `fetch` + `ReadableStream` 解析 SSE，按 `\n\n` 切块，`delta` 事件逐段拼到消息上 |

🔴 **风险（最高）**：`POST /chat/stream` 由**成员 1** 实现，**当前未落地**。
→ 联调前这条走不通。需成员 1 完成后一起验。

**演示话术点**（讲给评委）：
- 打开 DevTools → Network → 找 `stream` 请求 → **EventStream 标签**能看到 `delta` / `done` 逐条到达 —— 这是「真流式」的硬证据
- 不用 `EventSource` 的原因：它只支持 GET、不能带 `Authorization` 头

---

### 第 4 步：记住信息（记忆系统）

| 项 | 内容 |
|---|---|
| **在哪** | 对话页，对「小满」说 |
| **做什么** | 输入「我养了只猫叫豆豆」→ 发送 → 等回复完 → **再说**「我养了什么？」 |
| **看到什么** | ✅ 小满答出「豆豆」 |
| **验证隔离** | 切到「阿哲」→ 问同样的问题 → ✅ 答不出（记忆按人设隔离） |

⚠️ **风险**：契约 §7 的 `profileData` 目前是**空对象 `{}`**（画像字段未定义）。
→ 「用户画像页」展示的 `profileData` 可能是空的；**记忆（`/memory`）与画像是两个接口**，别混。

---

### 第 5 步：主动消息

| 项 | 内容 |
|---|---|
| **在哪** | 侧栏「主动消息」→ `/proactive` |
| **做什么** | 选人设 → 设置间隔/每日上限 → 保存 |
| **看到什么** | ✅ 保存成功提示；重新进页面能看到刚才的设置 |

🔴 **风险**：`TriggerNow` / `/proactive/trigger` 的**触发链路是空壳**（成员 3 的 PR #57 只交了定时扫描骨架）。
→ **演示时点不出「主动消息来了」的效果**。需要成员 3 补完触发链路。
→ `MASTER §4.2` L187 明确写：`/proactive/trigger` 是**硬性要求**（定时最短 30 分钟，现场等不起）。

**红点演示**：主动消息到达后，侧栏该人设名字旁出现红点，打开后消失。
⚠️ 依赖第 5 步的触发链路，同样卡住。

---

### 第 6 步：朋友圈

| 项 | 内容 |
|---|---|
| **在哪** | 侧栏「朋友圈」→ `/moments` |
| **做什么** | 打开页面，看动态流；点赞 / 评论 |
| **看到什么** | ✅ AI 之间的互动动态（数据由成员 3 提前灌） |

🔴 **风险**：`/moments` 目前仍是 `Placeholder`（路由已挂，页面未实现）。
→ 页面归**成员 3**；成员 2 负责**路由挂载 + 组件复用 + 确认显示正常**。
